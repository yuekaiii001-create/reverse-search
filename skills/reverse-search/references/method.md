# 五步法（AI 内部执行）

完整方法。SKILL.md 只保留骨架，这里展开。

注意：这五步是 **AI 的思考流程**，不是用户要走的手续。只有第二步需要用户参与，见 [questioning.md](questioning.md)。

## 第一步 · 需求剥离

**目的**：确认用户真正要的结果，不是关键词。

- 用户说的「找 X」是手段还是目的？「找房东」是手段，「不用中介费租到房子」是目的。手段可以换，目的不能丢。
- **硬约束**：地域、时间、预算、资质、底线
- **可交换条件**：哪些能让，哪些不能让

**同时指出红海**：直接搜会遇到什么 —— 中介、广告、钓鱼信息、内容农场、同质化竞争。说清楚，用户才知道为什么要绕路。

## 第二步 · 反转到供给方

需求方视角 → 供给方视角。

**核心问题**：谁手上有这个东西，而且现在正为它发愁？

| 供给方 | 手上有 | 发愁什么 |
|---|---|---|
| 房东 | 空置房源 | 每月房贷物业照烧，租不出去 |
| 二房东 | 转租权 | 转不出去就得自己扛租约 |
| 企业主 / HR | 岗位 | 招不到人，团队缺人影响交付 |
| 门店 / 经销商 | 库存 | 资金压死，清不掉 |
| 项目方 | 需求 | 找不到供应商 / 合作方 |
| 自由职业者 | 档期 | 空窗期没订单 |
| 正在注销的公司 | 设备 / 资产 | 急着变现 |
| 法院 / 资产管理 | 拍卖标的 | 流拍 |
| 内容创作者 | 流量 | 没有变现渠道，缺合作 |
| 出国 / 搬家的人 | 全套家具家电 | 带不走，时间卡死 |

**不要假设所有供给方都焦虑。** 这是待验证的假设，不是事实。输出时要标注出来 —— 猜错了用户能纠正你，写死了用户只能被动接受。

## 第三步 · 痛点推演 + 构造搜索词

从「发愁」推到「他会说什么话」。

人在焦虑时的行为模式：

- 去搜「怎么办」，而不是「买什么」→ 搜索词里带疑问句
- 去搜「别人怎么解决的」→ 找教程、经验帖、复盘
- 在别人的帖子下留言倾诉 → **评论区就是入口**

**搜索词公式**：

```
[目标资源] + [供给方身份] + [困境词] + [地域 / 时间]
```

不是每项都要有，但**至少要有困境词**。没有困境词，搜到的就还是红海。

困境词库：`急`、`转让`、`清仓`、`闲置`、`砸手里`、`怎么解决`、`有没有办法`、`求助`、`血亏`、`倒闭`、`失败`、`撑不住`、`空置`

对照：

| | 红海词 | 逆向词 |
|---|---|---|
| 租房 | `租房` | `房东 房子租不出去 怎么办` |
| 买公路车 | `公路车` | `车店倒闭 库存清仓` |
| 招人 | `招聘` | `团队缺人 项目卡住` |

完整构造方式见 [queries.md](queries.md)。

## 第四步 · 定位信息枢纽

发愁的人为了解决问题会去哪？那里才是真正的入口。

**关键判断：他会在哪里公开表达自己的困境？**

广告位不是枢纽 —— 那是供给方花钱买的摊位，站在那儿的全是专业卖家。
教程视频的评论区才是枢纽 —— 求助的人在那里主动暴露了身份、地点和具体困难。

分类和筛选方式见 [hubs.md](hubs.md)。

## 第五步 · 设计接触

以「能解决问题的人」的姿态出现。不是收割者，也不是救世主。

**救世主姿态和收割者姿态一样有害。** 前者居高临下，对方会本能抗拒，即使你的提议对他有利；后者对方迟早察觉，然后报复。

你要的是**真实交换**：他要解决一个麻烦，你要他手上的东西，双方平等。

这不是道德要求，是效率要求 —— 平等姿态的成交率高于救世主姿态。

具体话术和红线见 [outreach.md](outreach.md)。
