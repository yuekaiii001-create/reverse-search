# 启动判断

决定该不该启动本 skill。这一步做错，后面全错。

## 判据

> **这个领域里，存在「手上有货、正在为它发愁」的人吗？**

存在 → 启动。
不存在 → 不要启动，直接给常规答案。

## 该启动

- 找房、租房、买房
- 找工作、招人
- 找客户、找供应商、找货源
- 二手、库存、清仓、转让、拍卖
- 找合作伙伴、项目机会
- 用户已经搜过一轮，反馈是「全是中介 / 全是广告 / 都长得一样」

## 不该启动

| 情况 | 为什么 |
|---|---|
| 普通事实检索、导航、定义 | 没有交易对手方，逆向无意义 |
| 用户已经给了具体链接或目标 | 他已经有答案了，别节外生枝 |
| 用户要的是知识不是资源 | 「怎么学 Python」不是「找一个会 Python 的人」 |
| 用户只是随口一提，没有行动意图 | 别把闲聊变成咨询 |

## 逆向失效的情况（重要）

不是所有红海都能逆向。**逆向的前提是供给方过剩且焦虑。**

失效场景：

- **供给方稀缺且不愁卖** —— 热门学区房、紧缺牌照、爆款首发。这些人没有痛点，逆向无从下手。
- **需求本身没有供给方** —— 找一位二十年前的同学、找一份失传的资料。不是市场行为。
- **供给方是机构且流程标准化** —— 银行、政府、大医院。这些人不发愁，发愁的是排队的人。

**在这些情况下强行逆向，会给出比直接搜索更差的建议。**

判断错了就直接说出来，不要硬凑：

> 这个领域供给方不愁卖，逆向思维在这里没用。我们直接查官方渠道。

## 什么时候退出

| 触发 | 动作 |
|---|---|
| 用户已经拿到明确线索 | 切到尽调 → [risks.md](risks.md) |
| 用户明确说「你直接给我结果」/ 明显不耐烦 | 立刻切替身式，停止反问 → [questioning.md](questioning.md) |
| 用户开始问具体操作细节 | 说明他已经进入执行阶段，别再讲方法论 |
| 话题滑向违法或伤害他人 | 停止规划，说明不能协助，给合法替代方案 |
